# 三个 Agent 的执行顺序：先把自由画布做对

日期：2026-10-09。执行更新：用户已明确“你先一个人继续完成未完成的”，本会话接手本轮前后端实现；测试仍留给 Gemini。旧 Claude 写入归属不阻止这次经用户授权的接手。最新交付见 [独立接手交接](codex/handoff_batch3_solo.md)。

最新依据：用户明确「新建画布是空白，自己随便自定义」。本文件优先于第一批设计里「先选模板/范围/用途再建画布」的描述。

## 1. 现在的决定

「新建画布」默认直接得到可编辑的空白空间。名字可默认「空白画布」。不要求小说、剧本、章节、分镜计划、角色照片、故事描述、生成模型、模板或用途。

用户自己加文字、图片、视频、音频、素材引用、人物、地点、道具、白模、分组、子画布引用或生成节点；自己拖动、编辑、连线、复制、删除、保存。尚未实现的节点能力不能画一个假按钮冒充可用。自由编辑与运行生成分开，创建、加节点、连线和保存不自动派发 LLM 或 GPU 任务。

B/C是入口和工作视图，purpose只是分类，可默认为general；不决定用户必须放哪些节点。模板和「AI规划分镜」在用户主动选择后应用，不在新建的默认分支里自动执行。引用一份小说的角色，不自动把整张画布变成该小说的分镜计划。

世界/时期/身份与物理要求在相关资源、实例和生成操作上检查。未选择剧本不妨碍编辑、上传或引用现有素材。真正要编译连续剧情时才提示补齐必要的故事/世界/时间资料。

## 2. 静态查到的当前问题

- `NewCanvasModal.tsx` 默认页签是idea；blank只是另一个选项。
- `store.tsx:createCanvas` 的chapter参数默认继承当前章，并发送当前plan_id；入口中的「空白」仍可能带分镜来源。
- 旧后端custom创建时version=0/doc={}；版本0在前端代表「没有保存文档，按自动图布局」，没有区分真正空白与待初始化。
- 第一批production层对无小说画布只给共享媒体、不给已有角色引用；这限制了从素材库自由组合。
- Gemini第一批用IsolatedMockSession通过的契约检查，没有验证用户在实际界面新建、编辑、保存、重新打开的完整路径。报告中的BASE_READY或契约通过不能替代此路径，也不能证明真实SQL/事务/行锁通过。

以上是源码阅读结论，本方未运行测试。最新修正的后端与前端衔接见 [第二批交接](codex/handoff_batch2_free_canvas.md)。

## 3. 每一轮都按这个顺序

**本轮：Codex 前后端实现与集成 → Gemini 独立验收 → Codex 修复 → Gemini 复测。用户恢复外部并行后，再恢复三方约定。**

| 轮次 | Codex先交付 | Claude随后交付 | Gemini最后验收 | 本轮完成条件 |
|---|---|---|---|---|
| 1：自由空白画布，当前优先 | 明确空文档创建、真实版本、无小说可选素材与资源解析；保持旧接口兼容 | 默认空白、不继承计划、不强制模板/用途；自由添加/编辑/连线/分组、保存重开 | 真实点击创建，确认0节点0连线；手工编辑保存重开；无模型/GPU任务；旧分镜入口不回归 | 一个没有小说/剧本的用户能从零创建并保留自己画的内容 |
| 2：素材与多级引用 | 标准包/单格绑定、版本、跨画布引用身份、采用/失效边界；补建与返回槽位的真实执行契约 | A/B/C互相打开来源、角色库加入任意画布、引用已有图/单格、缺项补建返回 | 从角色库引用→消费者实际用同一AssetID；变更/冲突/删除和返回；补建若未接任务必须记未实现 | 一次真实素材到镜头的消费闭环成立，无下载再上传 |
| 3：站位、时间与运镜 | 共享SceneStage/事件状态、实例绑定、米/毫秒契约、动作和相机轨迹、SceneProtocol编译 | 3D导演台与时间线，用同一份数据改人物/机位/关键帧并回画布 | 3D编辑入口、保存回流、关键时点、视线/接触/遮挡/轴线、动画轨迹和真实渲染消费 | 白模和镜头使用同一场景/时间/相机数据，编辑有效 |
| 4：专业分镜与生成 | 剧本事件/因果→导演覆盖→能力编译；固定来源的导演/摄影/连续性知识，模式与依赖调度 | 专业分镜建议、所选范围运行、参考/控制能力限制、错误回到来源 | 验证剧情覆盖、人物/道具/位置、首尾状态、剪辑/切镜、异常复现；按排队约定生成小样 | 实际样片与事件/舞台/机位相符，而非仅任务成功 |
| 5：声音与成片 | 音频时钟、声音/口型路线、剪辑导出、恢复与结果采用 | 可编辑成片时间线、音轨、替换/锁定结果、导出和回到问题源 | 实际播放音画、时长、编码/导出、恢复、画面质量与用户需求 | 一条可编辑、可修复、可交付的完整短片链成立 |

不用三方一次写完所有阶段。每轮只交一个明确可操作路径；先让用户使用，再解决下一层。

## 4. 现在立即各做什么

**Codex**：本轮已独立接手自由画布、素材选择与消费、角色库直接引用、标准包生成回写；构建已通过，服务按任务空闲条件重载。详细源码、运行与验收边界以第三批交接和源码清单为准。继续不运行功能/视频测试。

**Claude**：本轮这些界面文件已由 Codex 接手，不要同时覆盖；用户恢复并行后先读第三批交接。旧任务描述：先读第二批交接，优先修`NewCanvasModal.tsx`、`store.tsx`、`contract.ts`、`api.ts`、`TopBar.tsx`的默认创建和初始化。新建用blank:true，不传当前plan_id；用途默认为general无需强制选择；保存用返回version；用户主动选AI规划时才走想法接口。无小说画布资产抽屉改用production资源选择，不依赖plan/cast为空的旧路径。其余大导航/全量3D改造不能挤掉这条最小路径。

**Gemini**：先更新验收矩阵，保留第一批报告但标明它验证的是旧源码与模拟数据。准备自由画布用例；Claude交付后做真实UI与隔离DB的同版本验证。不得仅因为89个关联测试通过，就发布新建画布或全部CR完成。当前修正无需GPU。

## 5. 怎样并行才不互相干扰

- Codex只写后端与权威文档；Claude只写前端/admin与本方交接；Gemini只写测试/本方报告。沿用 [文件归属](planA_agents.md)。
- Codex公布该轮源码契约后，Claude可以编码；Gemini可以同时准备该轮用例并检查已交后端。完整UI验收等两方的对应源码都交付后进行。
- Codex可先设计下一轮，Claude可做不依赖新接口的交互；冻结正在验收的契约，不能三方各自改同一字段。
- 需要跨归属修复，写具体文件/字段/输入/现象到自己的交接目录；对应owner修改，别人不要顺手覆盖。
- 同目录协作时不自行切分支、重置/变基、全仓格式化或同时提交。Codex在交接点统一保存来源清单和集成快照；没有共同快照仍不声称BASE_READY。
- 服务重启、迁移、共享模型/GPU任务由Codex统一协调；验证用隔离配置。不能为测试新功能自动恢复旧生产生成任务。

## 6. 每轮交接必须有

本方文件与来源、契约增量、实际调用参数、代码版本/源码摘要、已实现与未实现、独立验证证据及其范围。新建接口返回版本改变时，所有初次保存调用同步使用返回版本，不写死0。

状态分别记录：SOURCE_READY（可读源码）、接口运行、UI运行、独立真实路径通过、媒体质量通过。后两项没有证据不发布；存在未实现项也不写「全量完成」。
