## 3. 工作目录与共同基线

### 默认：独立 worktree / 分支

建议分支：`codex/plana-core`、`codex/plana-ui`、`codex/plana-qa`。实际工作目录在建立后记录，不把尚未创建的路径交给 agent 当成已存在。

当前工作区含大量 tracked 修改与 untracked 源码。**不能只从 main/HEAD 创建三个 worktree 并直接开工，也不能 git add 全目录把运行数据一起提交。**

由 Codex 集成方先做：

1. 在没有并行写入的交接点保留当前差异、来源与文件清单。
2. 整理现有制作相关源码和必要文档成为共同基线；保留既有作者改动，不夹带媒体输出、数据库、模型、日志、凭据或本机配置。
3. 记录基线提交/源码快照、包含哪些未提交文件、排除项及迁移现状。若某必要依赖是忽略文件，记录可复现配置方式，不把密钥复制进 Git。
4. 三路使用相同基线；各自保留本方提交与交接报告。
5. 发出 `BASE_READY` 后才正式实现；记录每路目录、分支、基线及负责范围。

共同基线提交步骤尚未执行；执行期已按下面的共享目录归属规则写入源码，不以现有HEAD冒充完整制作系统。

若用户已让三方在同一目录工作：立即执行上面的文件写入归属；允许依据明确契约实现各自模块，共享契约仅Codex更新，UI/QA通过本方交接目录提需求。不同时切分支、格式化全仓、安装依赖、暂存/提交/变基/重置；Git 操作统一由集成方串行负责。共享目录不具备工作树隔离，不能声称与独立 worktree 等价。合并前再在三方交接点收集来源与快照；没有快照的增量不能声称可独立cherry-pick。

## 7. 共享运行资源

- Git 隔离不隔离端口、数据库、文件存储和 GPU。每路工作树使用独立测试配置/端口，禁止自动抢占生产端口或清理其他 agent 的输出。
- 迁移链、主服务重启、共享网关改动由 Codex协调，Gemini不得独立在当前业务库执行迁移。
- Gemini在隔离数据库/媒体目录运行测试；生产数据只做获授权的只读检查，写入测试不落生产。
- 本机 LLM、FLUX、LTX、Blender 等重任务明确排队；真实媒体验证由 Gemini执行，使用双方交付版本。未经调度不同时启动多条 GPU任务。
- 不为测试启动带无关交易服务的整套容器，不自动使用付费端点。超出约定预算/范围显示阻塞或需调度，不能悄悄扩大运行。
- Codex和Claude可做读取、编辑和必要的静态交接准备；按用户要求，测试与真实质量评估归Gemini。后续若用户另有授权，记录职责变化。

## 8. 合并顺序与最终责任

由 Codex逐批合并，不等所有阶段全部完成才一次性拼接。

1. 契约与后端提交进入集成分支，核对迁移与向后兼容。
2. Claude对应 UI 提交进入同一集成版本；需要时解决接口与调用链冲突，不吞掉交接限制。
3. Gemini测试代码进入集成分支，对这个明确版本执行验证。
4. 问题按归属返回 Codex/Claude；修复后 Gemini针对相关路径回归。
5. 通过该批真实纵向路径才记录完成，继续下一批；分支合并成功不等于功能完成。

Codex负责最后核对：没有并行的第二套事实来源/契约/调度器，按钮到真实消费者可追溯，版本与状态正确，已知缺口明确。Gemini负责独立给出证据，不由实现方自己宣布质量通过。
