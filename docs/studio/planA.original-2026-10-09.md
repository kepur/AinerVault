# Plan A：一场戏一个舞台，每镜只是机位

> 目标：剧本里写的人、物、地方、动作，在每一镜里都站在对的位置、朝对的方向、做物理上说得通的事；
> 镜头之间的站位、光线、伤势、道具、动作势头接得上。
> 适用范围：一镜、几镜、一场戏、一章，或者只有一句想法（没有小说）。
>
> 写于 2026-10-09。本文只是方案；实现分阶段做，测试交给别的模型（见第 10 节）。

---

## 0. 一句话结论

现在的系统**每一镜各自搭一次景、各自写一段提示词**，镜与镜之间没有共享的「这场戏的世界」，所以站位、空间感、动作、尾帧互不相干，拼起来就是四不像。

改法：**一场戏只搭一个三维舞台**。剧本的动作排成这个舞台上的一条时间线（走位、拿东西、扇耳光、摔倒），**每一镜只是舞台上的一台摄影机加一段时间窗口**。首帧和尾帧都从同一个舞台的同一时刻渲出来，再把角色库里的脸「贴」进各自的人形区域，最后交给 LTX 在首尾帧之间补动作。这样连续性和物理规律由舞台保证，不再指望图像模型和视频模型去「理解剧情」。

```
镜头 N = 渲染(舞台 S, 时间窗 [t0, t1], 机位 C_N)
       ⊕ 身份（每个人只在自己的区域用角色库的定妆照）
       ⊕ 运动（舞台时间线在 [t0, t1] 里的动作 → LTX 分段提示词）
       ⊕ 声音（这段时间里的台词配音驱动口型）
```

## 1. 现在为什么四不像（真实数据上看到的）

| 现象（《坏蛋》第 1 场、滑雪测试） | 根因 |
|---|---|
| 镜 1 三个人画成四个，被霸凌者出现两次；镜 11 地上多躺一个人 | 关键帧只靠文字＋几张参考图，图像模型不知道画面里到底有几个人、各在哪 |
| 「领头少年」一镜是高个少年，下一镜成了李爽 | 分镜计划逐镜生成（`qwen3.8-flash`、不开思考），没有「这场戏谁是谁」的全局状态 |
| 镜 7 血从眼睛流出来；镜 5「扇耳光」画成直直举手 | 动作和细节只是文字，没有身体部位、接触对象、前后状态 |
| 白模镜头之间站位对不上、空间感乱 | 白模是**每镜单独让 LLM 搭一个新场景**（`from_shot.render_shot` → `planner.generate_protocol`），同一条走廊每镜都不一样 |
| 环绕运镜把画面拧翻、运镜空、和静态图差不多 | 运镜是文字，LTX 自己发挥；没有和人物的空间关系约束 |
| 镜头之间动作势头断、光线跳 | 下一镜不知道上一镜结束时人在哪、在做什么（尾帧接续 2026-10-09 才在 quick_film 里加了一种） |
| 特效（血、雪雾、摔倒）乱生成 | 特效没有「从哪儿来、持续多久、受什么物理约束」 |

**一个根因概括所有现象**：系统里没有一个「这场戏的世界状态」被所有环节共享。LLM、图像模型、视频模型各看各的一小段文字。

## 3. 分层结构（七层，每层只认上一层的产物）

```
L1 世界素材（翻译系统）   人 / 物 / 地点 / 时期造型 / 译名 / 物理尺寸
        │  定妆照 16 格、道具三视图、地点空镜＋平面图
L2 素材卡（有限、标准化）  每个素材一张「卡」：参考图、尺寸、别名、可用视角
        │
L3 场景舞台（一场戏一个）  布景平面 + 谁在场 + 动作时间线 + 连续状态（伤、湿、拿着什么）
        │  校验器：接触距离、速度上限、状态延续、人数、身高比例
L4 镜头覆盖（每镜一个）    机位 + 时间窗 [t0,t1] + 转场方式；180° 轴线检查
        │
L5 渲染配方（画布节点）    预演首/尾帧 → 分区身份首/尾帧 → LTX（首尾帧＋分段动作＋配音）
        │
L6 质检回路               视觉模型对照舞台状态检查：人数、左右顺序、朝向、道具、伤势；不过就换种子重出
        │
L7 画布                   以上每层都是可看、可改、可重跑的节点；改哪层，下游自动失效
```

每一层都是**数据**，不是一段提示词。提示词是 L5 在最后一刻从 L1–L4 编译出来的，人不直接写长提示词。

## 4. 数据契约

### 4.1 素材卡（L2）

```jsonc
{
  "id": "e:we_01M1NJRP0ZZ48NWVXQ6BGJNSNX",   // 世界实体 id；道具 p:…，地点 l:…
  "kind": "character",                         // character | prop | location
  "name": "李爽", "screen_name": "Brad Miller", "aliases": ["领头少年?"],   // 译名来自翻译系统
  "epoch": "baseline",                         // 本章用哪一期的造型
  "physical": {"height_m": 1.62, "build": "stout", "handedness": "right"},  // 道具：{"size_m": [0.9, 0.05, 0.05]}
  "views": {                                   // 可用的参考格（定妆照 16 格 / 道具三视图 / 地点空镜）
    "body_front": "/media/…", "body_side": "/media/…", "body_back": "/media/…",
    "face_front": "/media/…", "face_left": "/media/…", "face_right": "/media/…", "face_back": "/media/…",
    "expr_anger": "/media/…"
  },
  "look_en": "short stout boy, multicolor spiky dyed hair, grey graphic T-shirt, baggy jeans"
}
```

物理尺寸从哪来：
- 先由 LLM 从小说描写里抽（「瘦高」「矮胖」）；
- 抽不出来就按年龄和体型给默认值；
- 人可以在角色库里改。

**`physical` 用来定舞台里人偶的体型和身高**，镜头里两个人站在一起时的高矮差由舞台自然算出，不靠提示词去描述。

### 4.2 场景舞台（L3）

扩展现有的 3D-BOX 场景协议，一场戏一份。存在新表 `scene_stages`，按 `scene_id` 和版本存；`protocol_json` 直接是 `director/protocol.py` 的 SceneProtocol。

```jsonc
{
  "scene_id": "sc_01M1PKEFAEBQV5GMSDSGZKNE58",
  "set": {"location": "l:corridor", "preset": "school_corridor", "size_m": [3.2, 30, 3],
          "landmarks": [{"id": "lockers_left", "pos": [-1.5, 0, 0]}, {"id": "window_end", "pos": [0, 28, 1.5]}],
          "light": {"time_of_day": "day", "key": "overhead_fluorescent"}},
  "cast": [{"actor": "p1", "card": "e:…谢文东"}, {"actor": "p2", "card": "e:…高个少年"}, {"actor": "p3", "card": "e:…李爽"}],
  "props": [{"id": "money", "card": "p:wallet", "holder": "p1", "slot": "pocket_right"}],
  "beats": [   // 剧本动作排成时间线（秒）；每拍一句人话 + 结构化动作
    {"t": [0.0, 2.0],  "text": "两人把瘦弱少年逼到储物柜前", "do": [
       {"actor": "p2", "op": "walk_to", "target": [-1.1, 6.0], "speed": "walk"},
       {"actor": "p3", "op": "walk_to", "target": [-0.6, 5.2]},
       {"actor": "p1", "op": "back_against", "target": "lockers_left"}]},
    {"t": [2.0, 3.6],  "text": "高个少年：把钱交出来", "line": "a_dialogue_01", "do": [{"actor": "p2", "op": "talk", "to": "p1"}]},
    {"t": [5.2, 6.4],  "text": "高个少年扇了他一耳光", "do": [{"actor": "p2", "op": "slap", "target": "p1", "hand": "right"}],
     "effects": [{"kind": "blood_trickle", "on": "p1", "where": "mouth_corner_left", "from_t": 6.0}]}
  ],
  "state": {   // 由时间线推演出来的连续状态（校验器写，不是 LLM 写）
    "p1": [{"t": 6.0, "injury": "blood at left mouth corner", "persist": true}]
  },
  "axis": {"a": "p2", "b": "p1"}   // 主要对峙轴线（180° 规则）
}
```

`do` 里的动作是一张固定动作表（`walk_to / run_to / turn_to / look_at / talk / slap / push / grab / fall / sit / stand_up / pick_up / hand_over / ski_downhill …`），每个动作有物理前提和后果（见第 6 节）。LLM 只从表里挑动作、填参数，不写自由文本的动作。动作表对齐现有的 `ainer-studio/src/scene/rig.ts` 动作库，缺的补上。

### 4.3 镜头覆盖（L4）

```jsonc
{
  "shot_id": "sh_…", "order_no": 5, "scene_stage": "stg_…", "window": [5.0, 6.6],
  "size": "ms", "camera": {"from": "over_shoulder", "of": "p2", "on": "p1", "lens_mm": 50, "height": "eye", "move": "static"},
  "transition_in": "cut",        // cut 硬切 | match_action 动作接续（t0 = 上一镜 t1） | continuous 一镜到底 | time_jump 跳时
  "focus": "p1",
  "visible": ["p1", "p2"]       // 由 Blender 投影算出（不是 LLM 猜），给关键帧和质检用
}
```

`camera.from` 用一组机位语义（`wide_master / over_shoulder / single / two_shot / pov / insert / low_angle_hero …`），落地时由 `auto_frame` 换成具体位置，并检查每个人露出多少。

### 4.4 渲染配方（L5，画布节点）

沿用第三轮的配方节点，新增四种操作：

| op | 输入 | 产出 |
|---|---|---|
| `stage` | 剧本场次、素材卡、分镜表 | 场景舞台（L3 JSON），可在画布上看俯视图和时间线 |
| `coverage` | 舞台、分镜 | 每镜的机位和时间窗 |
| `previs` | 舞台、某镜、时间点 t | 预演图（灰人偶）＋每人一块区域遮罩＋深度 |
| `id_frame` | previs、素材卡 | 分区身份画面（首帧或尾帧） |

现有的 `video` 操作扩成 `first_frame + last_frame + segments + audio drive`。

## 5. 一镜是怎么出来的（编译流程）

1. **取舞台状态**：在 `t0` 和 `t1` 两个时刻，舞台推演给出每个人的位置、朝向、姿势、手里的东西、身上的状态（伤、湿、雪）。
2. **预演渲染**：Blender 按这一镜的机位在 `t0`、`t1` 各渲一张灰人偶预演，同时出每个人的色块遮罩和深度。人数和左右顺序到这里就定死了。
3. **按景别和朝向挑参考格**（小景别时裁局部，不硬画全景）：
   - 远景、全景：给全身格（body_front / body_side / body_back，按这个人在镜头里的朝向挑）；
   - 中景：全身格加正脸；
   - 特写、大特写：只给面部格（face_front / face_left / face_right，按朝向挑），再加这一刻的表情格（expr_anger 等）。底图换成预演里这个人那块区域的放大，**不再把空旷的大场景当底图**。
4. **分区身份**：每个人只在自己的遮罩区域里用自己的参考格（现有的 `flux2_regional`，最多 3 人；更多人时远处的人只留人偶色块加文字）。
5. **状态写进区域提示词**：「left mouth corner bleeding, a thin line of blood, eyes wet but not bleeding」只写进这个人自己那块区域，不会串到别人脸上。
6. **首帧和尾帧都这样出**。尾帧的人物位置来自舞台在 `t1` 的状态，不是让 LTX 自己猜。
7. **LTX 出片**：`first_frame` + `last_frame` 各钉一张，`segments` 写这段时间里每一拍的动作（由舞台时间线编译出英文，第一句主动作、运镜放最后），有台词就用配音驱动口型。时长 = `t1 - t0`。
8. **转场**：
   - `match_action` / `continuous`：下一镜的首帧直接用上一镜**真实出片的尾帧**（不是重新画的），动作势头、光线、飞溅物连贯；
   - `cut`：两镜都从同一个舞台渲出来，同一时刻、换机位，所以站位天然一致；
   - `time_jump`：舞台推演跳到新时刻，状态（伤势、道具）照样延续。

## 6. 物理与连续性规则（校验器，确定性代码，不靠 LLM）

舞台生成后先过校验器，有违规就把违规清单发回 LLM 改，最多改 3 轮，仍不过的标红给人看。

| 规则 | 例子 |
|---|---|
| 接触动作要先走近 | `slap / push / grab / hand_over` 执行时双方距离 ≤ 0.8 m，否则先插一个 `walk_to` |
| 速度上限 | 走 ≤ 1.5 m/s，跑 ≤ 6 m/s，滑雪下坡 ≤ 15 m/s；超了就延长时间或改成跑 |
| 不瞬移 | 同一个人在相邻两拍之间的位移必须有对应的移动动作 |
| 状态延续 | 受伤、湿身、沾雪、衣服破、手里的道具，从发生那一刻起延续到场景结束（或明确被处理掉） |
| 道具守恒 | 一个道具同一时刻只在一个地方；交出去就不在原来的人手里 |
| 人数守恒 | 镜头里看得见的人数由投影算，不由文字决定；关键帧和质检都按它来 |
| 身高比例 | 人偶体型按素材卡里的身高；同框时高矮差自然出现 |
| 180° 轴线 | 同一段对峙里机位不越轴；要越轴必须有过渡镜（中性机位或运动机位） |
| 视线 | `look_at` 的方向和对手在镜头里的位置一致（左边的人往右看） |
| 重力与跌倒 | `fall` 之后人在地上，直到出现 `stand_up`；摔倒方向由受力方向定 |
| 特效有来源 | 血从伤口、雪雾从滑雪板、水花从落水点出现，有起止时间，不能凭空出现或换位置 |

## 7. 质检回路（L6）

视觉模型（本机 Qwen3.6 / Gemma-4，多模态）**对照舞台状态**检查，不是只问「好不好看」：

- **关键帧**：
  - 人数对不对；
  - 从左到右是不是预期的那几个人（和定妆照比脸、发色、衣服）；
  - 朝向对不对；
  - 该有的道具和伤势在不在、位置对不对；
  - 有没有多手多脚、重复的人。
- **视频**：抽 4 帧，查同一个人前后是不是一个人、有没有突然多出一个人、有没有瞬移、首尾帧有没有被拉坏。
- **不过怎么办**：
  1. 换种子重出（最多 2 次）；
  2. 还不过，把违规写进区域提示词再出；
  3. 再不过，在画布上标红，等人改。

质检结果写进节点运行记录，画布上看得到。

## 8. 画布形态（L7）

画布就是这套数据的编辑器，纳逗式：

- **左侧素材区**（有限、标准化）：角色定妆照、道具三视图、地点空镜。都是从翻译系统的世界素材来的，也可以上传或用一句话生成。
- **中间舞台节点**：一场戏一个，打开是俯视平面图（人偶、道具、机位都能拖）和动作时间线（每一拍可改）。改了舞台，引用它的所有镜头自动失效。
- **右侧镜头节点**：每镜显示机位、时间窗、首尾帧、视频。连线从素材卡和舞台连过来，选中一镜能看到配方里 @ 了哪些素材、用了哪一格参考图。
- **范围随便选**：
  - 选一镜、几镜：按舞台补出这几镜；
  - 选一场：整场覆盖；
  - 选一章：逐场生成舞台；
  - 只有一句想法：LLM 先从想法生成素材卡和舞台，再走同一套。
- **改哪层，下游自动失效重跑**（第三轮执行器的 `recipe_hash` 已经支持）。

## 9. 实施阶段

每个阶段都能单独交付、单独测试。后一阶段依赖前一阶段的数据契约。

### P0 契约与素材卡（先做）

- 新增 `app/stage/` 包：
  - `cards.py`：从世界实体、时期造型、定妆照、译名组出素材卡；
  - `actions.py`：动作表，含物理前提和后果；
  - `schema.py`：舞台和镜头覆盖的 pydantic 模型。
- 素材卡的 `physical`：小说描写里抽 + 默认值 + 角色库可改。存 `world_entities` 新列 `physical_json`，需要迁移。
- 接口：`GET /api/v2/stage/cards?scene_id=…`。
- 验收：《坏蛋》第 1 场能列出 3 个人的素材卡（含译名、身高、可用视角）。

### P1 舞台生成与校验

- `app/stage/blocking.py`：本机 LLM（Qwen3.6，开思考）读剧本场次、对白、分镜表、调度表、素材卡，产出舞台 JSON。调度表 `ShotPerformance` 和分镜描述作为提示，LLM 负责把它们排成一条连贯的时间线。
- `app/stage/validate.py`：第 6 节全部规则，加自动修复回路。
- 新表 `scene_stages`（版本化），需要迁移。
- 接口：`POST /api/v2/stage/scenes/{scene_id}:block`、`GET …/stage`。
- 验收：第 1 场生成一份舞台，校验器零违规；「领头少年」在全场是同一个人；扇耳光前两人距离 ≤ 0.8 m；伤口出现后一直在。

### P2 镜头覆盖

- `app/stage/coverage.py`：把现有分镜（镜号、景别、时长、描述）映射到舞台时间窗和机位语义，用 `auto_frame` 落成具体机位，并检查 180° 轴线。
- 验收：14 镜都有时间窗，不重叠也不倒序（`time_jump` 除外），每镜可见人数由投影算出。

### P3 舞台出片（新的出片方案 `method="stage"`）

- 在 `canvas_run` 里加 `stage` 方案，和 keyframe、director 并列。流程按第 5 节：预演首尾帧 → 分区身份首尾帧 → LTX 首尾帧＋分段＋配音。
- 复用 `identity_frame.py`（尾帧也走一遍），按景别和朝向挑参考格。
- 转场：`match_action` / `continuous` 用上一镜真实尾帧。
- 验收：第 1 场 14 镜跑完，镜 1 人数、镜 5 打人的是高个少年、镜 7 血在嘴角，都由舞台保证。具体质量由测试模型评。

### P4 质检回路

- `app/stage/qa.py`：第 7 节，接进 P3 的流程和执行器。
- 验收：人为注入一张多一个人的关键帧，能被拦下并重出。

### P5 画布

- 舞台节点：俯视图加时间线编辑。
- 镜头节点：显示机位、时间窗、首尾帧。
- 素材区：素材卡分组展示。
- 范围选择：一镜、几镜、一场、一章。
- 和第三轮的配方节点、执行器合在一起：舞台、覆盖、预演、身份帧都是配方节点。
- 验收：在画布上拖动一个人偶的位置，只有引用这一刻的镜头失效、重跑。

### P6 道具和地点素材卡、想法直出

- 道具三视图（比照定妆照的做法）、地点空镜加平面图。
- 只有一句想法时：LLM 生成素材卡（人物照片 → 定妆照 16 格、服装、道具、地点）→ 舞台 → 覆盖 → 出片，全部摆成画布节点。替代现在的 `quick_film` 固定流水线（它保留为一个「一键」入口，内部改走这套）。

### 先后顺序与工作量（粗估）

```
P0 ─▶ P1 ─▶ P2 ─▶ P3 ─▶ P4
               └──────▶ P5（P2 之后可以并行）
```

## 11. 风险与取舍

| 风险 | 应对 |
|---|---|
| 本机 LLM 排一整场动作时间线不稳 | 动作只能从动作表里选；校验器兜底，最多修 3 轮；人可以在时间线上直接改 |
| 首尾帧差太大，LTX 中间会变形 | 时间窗控制在 5 秒以内；大动作拆成两镜，或中间多钉一张关键帧（网关支持 `keyframes`） |
| 分区身份最多 3 人 | 第 4 个人起只留人偶色块加文字描述；多人群戏拆镜 |
| Blender 渲染耗时 | 预演只要灰人偶，低分辨率；同一时刻多个机位一次渲完 |
| 舞台和现有分镜表冲突 | 舞台是新的一层，不覆盖分镜原文；冲突写进舞台的 `issues`，人看 |
| 和其他会话的改动冲突 | `quick_film.py`（Antigravity 在改）、第三轮文件（另一个会话的 agent 写的）只调用不改；本方案的新代码放在 `app/stage/` |
