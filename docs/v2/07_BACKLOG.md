## A. 剧本层：对话关系与表演信息

### 现状

v2 的 `ScriptBlock` 有 `speaker_tag`，知道**谁在说**，不知道**对谁说**。
`WorldEntity` 有 `appearance` / `voice_hints`，是角色的**恒定属性**，
不是某一刻的**瞬时状态**。

v1 更弱：`skill_03_scene_shot_plan.py` 用正则数关键词
（`action_hits` / `dialogue_hits` / `emotion_hits`），按命中数分类场景，
时长一律 `default_shot_duration_ms = 3000`。没有站位、没有对话指向、
没有表情动作与人物的绑定。**这套设计 v1 并不存在，不是移植而是新建。**

### 缺口

从剧本到分镜图，中间缺一层「这一刻画面里发生什么」：

| 维度 | 说明 | 为什么不能省 |
|---|---|---|
| 对话指向 | 谁对谁说，在场还有谁不说话 | 决定镜头给谁、给几个人 |
| 站位 | 人物在画面中的相对位置与朝向 | 前后帧站位跳变，动画就是穿帮 |
| 表情 | 该角色此刻的面部状态 | 同一张脸不同表情，i2i 才有变化 |
| 动作 | 此刻的肢体动作与手持物 | 首帧到尾帧的动作差就是这一镜的运动 |
| 视线 | 看向谁/什么 | 对切镜头的轴线靠它定 |

### 依赖顺序

素材基础包（人物/道具/服装的目标文化定形）必须先有，
表演信息才有附着对象 —— 说「他握紧了剑」时，
「剑」得先是一个有确定形态的素材，否则每一镜画出来的剑都不一样。

### 时长

前后分镜之间那几秒该多长，两条来源：

- **按剧情幅度自动**：`StoryBeat.tension_level` 与 `emotion_intensity` 已在库里，
  配合 `DirectorProfile.avg_shot_ms` 的分布，用赤字法分配 —— 张力高的段落切碎，
  张力低的给长镜头。这套在 `shot_plan` 里已有雏形。
- **人工覆盖**：任何一镜可手动设时长，锁定后自动分配不再改动它。

对白镜头例外：TTS 的真实时长是权威。语音说完了画面还在等，
或话没说完就切镜，都是硬伤 —— 所以 `AudioSpec.duration_ms` 反向决定
`Shot.duration_ms`，不参与自动分配。

### 落地拆解（已完成）

1. ✅ `shot_performances`：shot × entity → 站位 / 朝向 / 视线 / 表情 / 动作 / 手持物
2. ✅ `ScriptBlock.addressee_tags`、`present_tags`
3. ✅ `pipelines/performance.py`：对话指向与表演分两步抽，依据不同 ——
   对话指向是文本层的事实，站位要按镜头统一
4. ✅ 首帧读 `expression/action`，尾帧读 `expression_end/action_end`；
   取错字段首尾帧会一模一样，生成出来是两张静止的画
5. ✅ 站位跳变检测 + 后台告警。判据是「位置突变且 action 里没写走位」

两个告警在实现时才想清楚它们各自意味着什么：
- **首尾相同** → 这一镜没有表演。首尾之差就是运动，相同则 i2i 无从改起
- **站位跳变** → 动画会穿帮。除非中间有明确走位，那就该写进 action

分批抽对话指向时要**带上前一批的尾部**：在场判断依赖上文（谁进过场、谁走了），
切断上下文会让每批的第一段都判成「只有说话人在场」。

## B. 称呼在呼语位与叙述位的形式差

已实现的称呼变体给每条称呼一个目标形式，但英语里同一称呼在两个位置形式不同：

    呼语位：'Master, I shall go.'        ← 直接称呼，裸用
    叙述位：His master pushed the door.  ← 作主语，要带限定词

当前模型只给一个形式，叙述位会译出 `Master pushed open the door`，读着别扭。
需要在 `entity_appellations` 上区分 vocative / referential 两种形式。

## D. 时期与配音之后剩下的

### 脸参考图 · 已做（identity.py）

生成正面素颜头肩像作为跨期共用的锚，挂到该角色的**每一期**上 ——
只挂第一期的话，中年那一镜取到的锚是空的，于是从文字重新生成一张脸。
一个人一个锚是覆写而不是报警：锚分叉直接导致脸漂，正确答案没有歧义。

有锚之后，出图提示词不再重复描述脸：**参考图负责「是谁」，
文字负责「在做什么、穿什么」**。

**还差最后一步**：后续各期目前是把锚作 `reference_images` 带进 t2i，
而不是真正从锚做 i2i。带参考图已经能把脸拉近，但 i2i 才是锁死。
等接了真实图像模型（现在走的是 mock 端点，产出是占位图），
要按各家对 reference/i2i 的支持在中间层选路 ——
契约里 `image.image_to_image` 已有 `last_frame` 用途，加一个
`epoch_from_anchor` 即可。

### 时期只在人物上跑过

`AssetEpoch` 现在两种主体都支持（`subject_key` 指向素材或人物），
但素材那一侧仍然没有真实数据 —— 全库没有一个 `asset_spec` 绑过实体，
`seed_baseline_epoch` 从未在管线产出的数据上跑过。
「探访故乡要与二十章前是同一个院子」这条路径因此还没被验证过。

### 配音落到具体引擎

`to_tts_params` 给的是相对偏移与 style_prompt，是引擎无关的。
接 qwen3-tts / 云 TTS 时需要一层映射，把它落成那家的取值，
并把结果写回 `voice_ref` + `voice_engine` ——
换引擎时据此判断哪些要重新落地，而声学描述本身不动。

### EntityChapterState 的去留

人物外观现在有三套机制：`EntityWorldVisual`（无时间）、
`EntityChapterState`（v1 的按章增量、自由文本）、`AssetEpoch`（v2，不变/可变分离）。
`_entity_look` 已经改成「有时期就只用时期」，避免同一张脸被描述两遍。
但两套旧机制仍在库里，长期应当把 `EntityChapterState` 的数据迁进时期后删除。
