# 完整翻译流

从中文原稿到「目标文化圈层的读者拿到同一个故事」。

十一步，每步只做一件事，每步的产物都能单独审、单独锁。
分这么细不是为了工程整洁 —— 是因为**合并任何两步都会让模型在还没弄清
「这是什么」的时候就开始想「怎么译」**，而那正是所有翻译事故的源头。

```
① 分块      规则切段，零成本
② 实体      人物/场景/道具/势力 + 称呼变体（谁怎么叫谁）
③ 装置      笑点、反转、伏笔的「机制」
④ 梗        字面义 ≠ 实际用法的说法
⑤ 词表      名物：客栈→inn、捕快→bailiff
── 以上只看原文，与目标文化无关 ──
⑥ 命名      家族共姓 + 称呼各自定形
⑦ 呈现      每个梗在目标圈层怎么办（九档）
⑧ 门禁      映射审完了吗？没审完不许翻
── 以下才开始生成译文 ──
⑨ 翻译      占位符 + 词表 + 骨架 + 装置 + 梗表 一起注入
⑩ 三审      违规审查 → 回译校验 → 文化差异审查
⑪ 裁决      人对每条差异拍板，再一并落地
```

---

## 为什么②③④要在原文上做

**原文是唯一事实源。** 在译文上抽实体，译文错了素材跟着错，而且不可追溯 ——
你拿到一个叫 Lin Fan 的角色，无从知道它本该叫什么。

更要紧的是：**②③④抽的是「这是什么」，⑥⑦定的才是「怎么办」。**
合并的话，模型会一边猜这个梗是什么意思一边给译法，
结果是直译一个它自己都没弄懂的东西 —— 而且译文读着通顺，看不出问题。

---

## ④⑦：梗能不能翻，翻还是解释

「能不能翻」不是是非题，是**选哪一档**的问题。九档策略，代价递增：

| 档 | 做法 | 出戏 | 什么时候用 |
|---|---|---|---|
| `preserve` | 照搬 | 无 | 目标文化同样成立（emo 本就是英语借词） |
| `substitute` | 换等价说法 | 无 | 有承担同样功能的现成说法（yyds → GOAT） |
| `transplant` | 换目标文化的梗 | 无 | 没有等价物，但有同类的梗可移植 |
| `naturalize` | 按目标习惯重写 | 无 | 连同类都没有，只能重写（躺平 → screw it） |
| `gloss_inline` | 行内轻注 | 轻 | 必须让读者知道背景，但不想打断 |
| `footnote` | 正文保留＋脚注 | 重 | 这个典故本身就是内容 |
| `compensate` | 就近补一个同效果的 | 无 | 此处认赔，总量守恒 |
| `relocate` | 移到别处实现 | 无 | 这里放不下，换个地方 |
| `omit` | 舍弃 | — | 强行保留反而伤害阅读 |

**选错的代价不对称**：该 substitute 的用了 footnote，读者出戏；
该 gloss 的用了 preserve，读者一脸茫然还以为自己没读懂。

### 决定用哪档的是三个维度，不是一个

只看「文化依赖度」会做出两类错判：

**第一类：高依赖 + 承载情节。** 按依赖度该「舍了补偿」，
但那是伏笔 —— 舍了后文回扣就落空。读者不会想「这里少了个梗」，
只会觉得「后面那段莫名其妙」。所以承载情节的**永远不能 omit**，
宁可 gloss_inline 出戏。

**第二类：高依赖 + 短命网络梗。** 按依赖度该费力找等价物，
可这梗在源文化里都快死了 —— 不值得目标读者付理解成本，直接 naturalize。

```python
choose_strategy(cultural_load, plot_load, volatility)
```

`plot_load`：none 纯修辞 / flavor 塑造 / setup 伏笔 / pivot 转折靠它
`volatility`：evergreen 成语典故 / decade 一代人 / years 数年 / months 短命

### 网络梗的三个额外麻烦

- **会过期**：判断依据是「五年后的读者还认识吗」，不是「现在火不火」
- **分平台分圈层**：同一句话在饭圈是褒、在游戏圈是贬
- **目标文化的对应物也可能过期**：拿一个明年就死的英语梗去替中文的经典说法，
  等于把过期问题原样搬过去。所以渲染时要记 `target_volatility` 并告警。

## ⑨ 翻译时注入什么

```
占位符   人名替换成 {{CHAR:xxx}} 后才进模型，人名根本不参与翻译
         称呼变体各占一个占位符 —— 师父叫「小天」还原成 Tom 而非全名
名物表   只注入这批文本里真命中的条目，全量注入会淹掉相关的那几条
梗表     九档策略连同目标文本一起给，标「舍弃」的明确交代不译
骨架     情节因果与情绪曲线（仅改编模式）
装置     笑点与反转的机制，不是文本（仅改编模式）
```

**梗表两个模式都注入**，因为它不是「发挥空间」而是硬约定 ——
「破防了」直译成 defences breached 在逐句模式下也是错的。
骨架与装置只在改编模式给，逐句模式给了会诱导模型自由发挥。

## ⑩ 三道审查，各查各的

| 审查 | 查什么 | 能否自动修 |
|---|---|---|
| 违规审查 | 音译残留、名物没换、锁定译名没用上 | 能，有对错 |
| 回译校验 | 情节点是否丢失、装置是否落地 | 能，可机器比对 |
| **文化差异** | **两边读者各自得到了什么** | **不能，只有判断** |

前两道有对错，机器判定后可以直接改。第三道没有对错 ——
「原文的读者会笑，译文的读者不会」这件事，只能提方案，不能自动改。

### 文化差异审查的问法

**不问「翻得对不对」，问「两边的读者各自得到了什么」。**

问对不对，模型会去比对字面，然后告诉你「忠实准确」；
问读者得到什么，它才会去想那句话在两个文化里各自激起什么反应 ——
落差就是要找的东西。

十二类差异：笑点丢失 / 情绪抹平 / 语体错位 / 关系丢失 / 言外之意丢失 /
典故读不懂 / 梗直译了 / 缺文化前提 / 年代错置 / 禁忌错位 / 节奏改变 / **过度解释**

最后一类要专门查。大多数审查只会说「不够充分」，于是每轮都加解释，
几轮下来译文比原文长一半，全是把留白说破的句子。原文没说的话，译文也不该说。

## ⑪ 人工裁决：四态，不是两态

```
同意   方案照用
修改   人给一个更好的，以人为准
补充   方案对但不完整，人加一条
驳回   方案错了或此处无需处理
```

**「补充」不能省** —— 它是最常见的一种。模型指出了问题、给的解法只对一半，
只有同意/驳回两个选项时，人只能选驳回然后从头写，等于白审一遍。

裁决为「修改」或「补充」时必须写出文本，否则应用时无内容可用 ——
API 直接拒绝，而不是静默跳过让人以为改上去了。

落地时**锁定过的块不覆盖**：那是人工校对过的，审查方案不该越过它。

## 模型分档

成本与质量不成正比：分块、切镜这种活，强模型的产出与快模型没有可觉察差别；
而文化差异审查、名物定译，快模型给的结论似是而非 ——
读着头头是道，错的地方要等读者笑不出来才发现。

```
draft     批量、结构化、错了立刻能发现   分块 切镜 素材参数
standard  默认档                        实体抽取 名物挖掘
premium   判断吃重、错了藏得住          命名 装置 梗 翻译
critical  结论决定要不要返工            文化差异审查 回译校验
```

路由是 `能力 × 用途 × 档位 → 端点`，四步回落：

```
(用途,档位) → (用途,*) → (*,档位) → (*,*)
```

**用途优先于档位**是有意的：给翻译单接了一个调过的模型时，
它应该胜过任何档位规则。只接一个模型的话，填一条 `(*, *)` 兜底即可。

## 实测（中文网络 → 现代美国英语，DeepSeek）

原文含 7 个网络梗。抽取判定全对，渲染结果：

```
顶      substitute  → That's fire
yyds    substitute  → GOAT
破防了   substitute  → I'm tilted
emo     preserve    → emo（本就是英语借词）
卷起来   substitute  → embrace the rat race   ← 伏笔
内卷     substitute  → classic rat race       ← 与前文保持链接
躺平     naturalize  → screw it
```

译文零直译、零违规。文化差异审查给 **72 分**，5 处差异 —— 而且它指出的
三件事都对：`躺平 → screw it` 抹掉了主题共鸣（该用 lie flat）、
「哥」的亲近感丢了两次（这一章确实没跑称呼抽取）、
`破防了 → tilted` 的情绪从「难过」偏成了「恼火」。

第三条尤其说明问题：tilted 这个译法看起来精准，实际偏了 ——
这正是只有终审档模型才查得出、而快模型会放过的那类错误。
