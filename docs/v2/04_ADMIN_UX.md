# 04 · 后台重设计

> v1 的问题不是"页面丑"，是**信息架构错了**：42 个页面按后端模块切分，用户在一个章节上干活要跳 6–8 个页面。
> v2 的核心主张：**一本书、一个章节、一个工作台，不跳页。**

---

## 1. 诊断：v1 的用户路径

用户要把「第 12 章」做成英文视频素材，在 v1 要走：

```
小说管理 → 章节管理 → 章节编辑 → 转译工作台(建项目/配置/跑) → 世界观页
→ 章节预览(分镜) → 提示词库 → 实体提示词工作台 → 资产库 → 运行中心(看任务)
→ NLE 时间线 → 配置中心(改模型) → 回到运行中心重跑
```

**12 次跳转，每次丢失上下文，且没有任何一个页面能回答"这一章现在到底做到哪了"。**

---

## 2. v2 信息架构：5 个区

```
┌─ 侧边栏（固定，5 项，不折叠） ────────────────────────────┐
│  📚 书架        Library     — 小说 / 章节 / 导入            │
│  ✍️  工作台      Workbench   — ★ 核心，章节内做完一切         │
│  🌍 世界观      World       — 人物 / 地点 / 道具 / 风格卡片   │
│  🎬 素材        Assets      — 生成结果总览 + 任务队列        │
│  ⚙️  设置        Settings    — 中间层端点 / 能力路由 / 提示词  │
└──────────────────────────────────────────────────────────┘
```

**只有 5 个入口。** v1 的 42 个页面，映射关系：

| v2 位置 | 吸收的 v1 页面 |
|---------|--------------|
| 书架 | NovelLibrary, NovelDetail, ChapterManager, ChapterWorkspace |
| 工作台 | ChapterEditor, TranslationProject, Translations, ChapterPreview, ChapterRevision, TimelinePatch, NleTimeline, ProductionBoard |
| 世界观 | RoleStudio, RoleConfig, VoiceBinding, EntityPromptWorkbench, EntityPromptLibrary, AssetBindingConsistency, CulturePack, Persona |
| 素材 | AssetLibrary, AssetTimeline, RunCenter, ContentRun, RunSnapshot, RunPreview, OpsBridge, AuditLogs |
| 设置 | Config, ModelCatalog, ModelRouting, ModelsAndProviders, ProviderRouter, LanguageSettings, NotificationSettings, PromptAssets |
| 冻结不迁移 | KBAssetCenter, KnowledgeCenter, RagPersona, Dashboard |

### 3.2 四个 Tab，同一份上下文

| Tab | 内容 | 主操作 |
|-----|------|--------|
| **原文** | 章节正文编辑器，可标记场景分隔 | 编辑、重新分章 |
| **译文** | 左右对照，逐块。`action` 类型块置灰不参与 | 翻译 / 锁定 / 标已审 |
| **剧本** | Scene 卡片 + Block 流，可拖拽调整归属，改说话人 | 生成剧本、拆并场景/块 |
| **分镜** | Shot 卡片网格，每卡显示首帧/尾帧缩略图 | 生成分镜、生成素材 |

**关键：Tab 切换不换页、不丢滚动位置、不重新请求整章。** 左侧场景导航和右侧上下文面板**在四个 Tab 中始终存在**。

- 状态用色：灰=未生成 / 蓝呼吸=生成中 / 绿=就绪 / 黄=有 warning / 红=失败

## 4. 六条交互铁律（对治"反人类"）

### 铁律 1 — 生成动作就地触发、就地出结果
任何 `:generate` 都**不跳转到"运行中心"**。原地变成呼吸态，SSE 推完直接替换成结果。运行中心只是事后审计与批量重试的地方，不是工作流的必经站。

### 铁律 2 — 长任务不阻塞界面
顶栏常驻"⟳ N 任务运行中"，点开是右侧抽屉（任务列表 + 进度 + 失败原因 + 重试）。用户可以在等首帧的同时继续校对译文。

### 铁律 3 — 参数表单由 `param_schema` 自动渲染
后台**不为任何厂商写专用页面**。设置页读 `GET /settings/capabilities`，按 JSON Schema 渲染控件（integer→滑块、enum→下拉、number+min/max→滑块、带 `title`/`description` 的显示中文标签）。
> 换一家厂商 = 中间层更新 Discovery。后台零改动、零发版。**这条是整个后台可维护性的地基。**

### 铁律 4 — 人工编辑永不被 AI 静默覆盖
任何被人改过的 Block / Scene / Shot / FrameSpec 打 `edited_by_human`，UI 上带 ✎ 标记。重新生成时默认继承，若确实要覆盖，弹窗列出"将丢弃 N 处人工编辑"并要求确认。

### 铁律 5 — 一个动作只有一个入口
v1 有三个地方能改 prompt（提示词库 / 实体工作台 / 分镜预览），三处数据还不同步。v2：
- 实体的稳定外观 → 只在**世界观**改
- 单个镜头的临时描述 → 只在**分镜卡**改
- 系统级提示词模板 → 只在**设置**改
- 名物译法 → 只在**世界观 › 名物词表**改（不在译文页临时改，否则下一章又漂）

### 铁律 6 — 每一屏都要能回答"现在到哪了、下一步做什么"
书架的章节列表画状态四联进度条；工作台顶栏画阶段管线：

```
原文 ✓ ── 剧本 ✓ ── 译文 92% ── 分镜 ✓ ── 素材 38/42 ⚠1
                                                  ↑ 点这里直接跳到失败的那个
```

## 5. 世界观页

卡片网格，一个实体一张卡，**不需要 join 6 张表**：

```
┌─ 李白 · 角色 ─────────────── 🔒 ─┐
│ ┌────┐┌────┐┌────┐             │
│ │参考││参考││参考│  + 生成       │
│ └────┘└────┘└────┘             │
│ 外观: tall Tang-dynasty poet,   │
│       white robe, sword...   ✎  │
│ 音色: Ethan·沉稳男声  ▶ 试听  ✎  │
│ 译名: en-US Li Bai              │
│       ja-JP リ・ハク         ✎  │
│ 出场: 第 1,3,5,12 章            │
└─────────────────────────────────┘
```

译名字段**与翻译线是同一份数据**（`entity_world_names`）—— 在这里改，全书译文的人名一致性检查立即生效。这是 v1 里被拆成两套系统的东西。

### 5.1 世界观区的三个 Tab（★ 详见 `06_WORLDVIEW_TRANSLATION.md §7`）

世界观不只是"人物卡片墙"，它是**世界观转译的操作台**：

**Tab 1 · 世界观映射** —— 一本书可并列多张卡，各自独立
```
┌ 中国·唐·古典  ──▶  日本·昭和 (1926–1989) ───── active v3 ─┐
│ 命名 文化等效   敬语 映射   名物 严格                       │
│ 覆盖  人名 42/42 ✓   名物 218/240 ⚠   称谓 16/16 ✓         │
│ 违规  高 0   中 4   低 11                                  │
│ [导入预置词表] [从章节挖掘] [RAG 补全] [全书重扫] [发布新版]  │
└────────────────────────────────────────────────────────┘
┌ 中国·唐·古典  ──▶  欧洲·中世纪盛期 ────────── draft v1 ─┐
│ 覆盖  人名 12/42   名物 30/240                            │
└────────────────────────────────────────────────────────┘
```

**Tab 2 · 名物词表** —— 可编辑表格，这是 v1 完全没有的一屏
```
canonical_key          类别   原文   译文    读音      禁用词        状态   命中  依据
place.lodging_venue    场所   客栈   旅籠   はたご   inn,hotel     🔒锁定  128   ⓘ
office.magistrate      职官   县令   代官   だいかん  magistrate   ✓通过   34    ⓘ
currency.copper_coin   货币   铜钱   文     もん     copper coin  ✓通过   61    ⓘ
weapon.straight_sword  兵器   长剑   直刀   ちょくとう —          ○候选   7     ⓘ
```
点 `ⓘ` 展开证据：命中的原文出处（可跳转到块）+ RAG 来源文档 + rationale。
批量审核：候选 → 通过 → 锁定。锁定后任何重译都不会改动它。

**Tab 3 · 人物名录** —— 按 `family_key` 分组，家族姓氏一致性一眼可见
```
▾ 李家 (li_family) → 綾小路
    李清照  →  綾小路 静    あやのこうじ しずか   🔒 已锁定  ▶试听
    李格非  →  綾小路 格    あやのこうじ ただし   ✓ 已通过  ▶试听
▾ 赵家 (zhao_family) → 高遠
    赵明诚  →  高遠 誠      たかとお まこと      ○ 3 个候选待选
```
候选名带 rationale（"昭和初期知识阶层常见名，与角色书香门第身份匹配"）。
`[检查家族一致性]` 按钮扫出"同族不同姓"的情况。

**违规面板**与工作台的译文 Tab 共享同一份数据：点任一条违规，直接跳到出问题的那一块原文。

## 6. 设置页

三块，就三块：

1. **中间层端点** — 一行一个 gateway：URL / 密钥 / [测试连接] / 能力数 / 上次同步时间 / [刷新能力]
2. **能力路由** — 一张表：`能力 × 用途 → 端点 + 模型 + 默认参数`
   ```
   image.text_to_image  首帧      primary  seedream-4.0    [参数▾]
   image.text_to_image  场景背景   primary  seedream-4.0    [参数▾]
   image.image_to_image 尾帧      primary  seedream-4.0    [参数▾] strength=0.35
   audio.tts            对白      primary  fish-speech-1.5 [参数▾]
   text.chat            剧本生成   primary  claude-opus-5   [参数▾]
   text.translate       翻译      backup   deepseek-v3     [参数▾]
   ```
   `[参数▾]` 展开的表单，**完全由 Discovery 的 `param_schema` 生成**。
3. **提示词模板** — 剧本生成 / 实体抽取 / 术语挖掘 / 翻译 的 system prompt，可编辑可回滚。

## 7. 技术选型建议

- 保留 Vue 3 + TS（团队已有），但**新建 `studio-web-v2` 目录**，不在旧代码上改
- 组件库：Naive UI 或 Arco（表格/表单/抽屉齐全，暗色好看）
- JSON Schema 渲染：`@lljj/vue3-form-naive` 或自写 200 行（能力参数只有 number/integer/enum/string/boolean 五种，自写更可控）
- 状态：Pinia，**按业务域切 store**（`useChapterStore` 持有当前章节的全部数据，四个 Tab 共享）
- SSE：原生 `EventSource`，一个全局连接推所有任务状态
